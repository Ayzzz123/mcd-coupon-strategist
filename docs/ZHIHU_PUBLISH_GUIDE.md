# 知乎发布操作清单

> 配合 `docs/ZHIHU_POST.md` 使用

---

## 一、发布形式：选「文章」，不要选「回答」

原因：

| | 回答 | 文章 |
|---|---|---|
| 能否被搜索引擎收录 | 差 | **好** |
| 能否加封面图 | 不能 | **能** |
| 站内推荐权重 | 依赖问题热度 | 独立分发 |
| 适合内容 | 针对性问答 | 项目分享 |

你这篇是「我做了个东西」的分享型内容，**发文章更合适**。

如果一定要发回答（能蹭流量），找这类问题下手：

- 「有哪些值得推荐的 GitHub 开源项目？」
- 「麦当劳的优惠券怎么用最划算？」
- 「MCP 是什么？有哪些实际应用？」
- 「2026 年有什么有趣的开源项目？」

---

## 二、知乎编辑器会把 Markdown 弄乱，用这个流程

知乎的富文本编辑器**不认 Markdown**，直接粘贴会变成一坨。正确做法：

1. 先打开 https://md.aclickall.com/ （Markdown 转知乎格式的工具）
2. 把 `ZHIHU_POST.md` 里 `## 正文` 之后的内容粘进去
3. 点「复制」按钮 → 粘到知乎编辑器
4. **代码块需要手动重新设置为「代码」样式**（知乎的代码块要用工具栏那个 `</>` 按钮，否则会丢等宽字体）

### 刻意避开的知乎坑

我在文案里已经做了这些规避，你粘贴时留意别破坏：

- **没用 Markdown 表格** —— 知乎粘贴表格会错行，所以「技术坑」部分改成了编号小节
- **没用行内代码反引号** —— 知乎不渲染 `` ` ``，会原样显示成反引号，所以字段名都写成普通文字
- **代码块用 ``` 包裹** —— 转格式工具能识别，但粘完要检查一下

## 三、封面图

知乎文章**必须传封面**，否则在信息流里只有一行字，点击率很低。

- 首选：`assets/social-preview.png`（1280×640，刚好符合知乎封面比例）
- 备选：仓库 README 顶部 banner（但它更长，会被裁）

正文中间建议插两张图，位置：

1. 第「二、券是有保质期的钱」之后 → 插 `assets/demo-dual-view.svg` 导出的 PNG
2. 第「六、项目地址」之前 → 插 `assets/architecture.svg` 导出的 PNG

> ⚠️ SVG 不能直接传知乎，需要先转成 PNG。可以让我帮你转。

## 四、发布时机

知乎的推荐机制是**发布后 1~2 小时内的互动数据决定后续分发量**。

所以：

- **别在深夜发**（没人看，初始数据差，直接判死）
- 推荐 **工作日 12:00-13:00** 或 **20:00-22:00**
- 发布后立刻分享到自己的微信群/朋友圈，**前 30 分钟的点赞和评论最关键**
- 前几条评论自己要回复，知乎很看评论区活跃度

---

## 五、发布后必做：在 GitHub 加 Discussion 引导

知乎那篇文章里放了仓库链接，但**知乎的外链是 nofollow 的**，且会弹「即将离开知乎」提示，跳转流失很高。

对策：在仓库里开一个 Discussion 置顶，标题类似：

> 「从知乎来的朋友，欢迎在这里留言」

然后引导他们 **先点 star 再提问**。这条对转化率提升很明显。

## 六、同步分发渠道（一稿多投，改标题即可）

同一篇内容，改个开头就能投：

| 平台 | 调整点 |
|---|---|
| **掘金** | 标题加「实战」二字，开头去掉「先说结论」的知乎腔，直接上技术 |
| **V2EX / 分享创造** | 标题改成「[分享] 麦当劳 MCP 省钱助手，反凑单陷阱」，纯技术口吻，别提「知乎」 |
| **即刻** | 只发前两段 + 项目链接，配 social-preview 图 |
| **小红书** | 需要重写成短句 + emoji 风格，标题「谁懂啊…我发现麦当劳的券会过期」 |
| **B 站专栏** | 和掘金版本一致 |
